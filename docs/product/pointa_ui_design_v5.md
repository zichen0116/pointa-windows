# 映点 Pointa · UI/UX 交互设计说明（第五版）

- **版本**：V5（2026-10-28）
- **对应原型**：`pointa_ui_prototype_v5.html`
- **设计基准**：以 `pointa_ui_prototype_v4.html` 为完整基线，仅修改 Windows 小窗底部留白与默认黑色主题；其余布局和交互承袭 V4。
- **技术目标**：Android Kotlin + Jetpack Compose；Windows C# + WinForms。
- **交付状态**：可离线打开的 HTML/CSS/JavaScript **高保真交互原型**；连接状态、扫码、激光移动、翻页、陀螺仪、Windows 系统托盘均为可视化模拟。未接入真实设备或硬件系统接口。

### 设计取舍

维持 V3 的统一工作台、手机外框、控制模式命名与编辑交互。每次修改优先替换被指出的布局和行为，避免影响其他已确认的操作路径。此版本**主题色与激光色分离**：切换主题更新 UI 控件强调色，原型中模拟激光点仍采用默认的红色；后续需要自定义激光颜色时可另设选项。

## 2. 全屏模式

### 2.1 尺寸调整

在桌面原型的 **336 × 706 px** 手机模拟框下，第一版和 V3、V4 实际浏览器布局测量如下：

| 对照 | 触控区宽度 | 触控区高度 |
|---|---:|---:|
| 第一版 | ≈284 px | ≈336 px |
| 第三版 | ≈284 px | ≈403 px |
| **第四版** | **≈284 px** | **≈336 px** |

V4 采用以下内部定位值（以手机模拟框内容区域为基准）：

```css
.fullPad { top: 172px; left: 18px; right: 18px; bottom: 182px; }
.fullPager { bottom: 70px; height: 73px; }
```

这里的像素值仅用于**固定尺寸原型**，原生端应根据屏幕可用区域、系统安全区和密度做自适应布局。缩小触控区后，翻页按钮上移以恢复第一版紧凑的触控区—翻页区间距。沿用 V3 的水平和垂直细十字参考线、上下页的不同尺寸权重，以及按下显示 / 抬起隐藏激光点的交互。

### 2.2 操作规则

- 手指按住触控区并移动：光点在触控区内跟随移动，生成模拟拖尾。
- 抬手、取消触摸：光点隐藏；开启拖尾时已生成的拖尾逐渐消散。
- 点击底部上一页 / 下一页：出现模拟动作提示，触摸指针不会因此移动。
- 切换模式不改变“已连接”的原型展示状态。

## 3. 单手模式

### 3.1 镜像布局

- **左手**：左侧触控区，右侧纵向上一页 / 下一页。
- **右手**：左侧纵向上一页 / 下一页，右侧触控区。
- 默认侧栏占工作区宽度约 24%，触控容器占剩余宽度，二者之间保持 **9 px** 间距。
- 与 V3 一致：工作区从模式栏下方开始，不额外插入无效的上方空白。

### 3.2 V4 新增：侧栏宽度跟随相邻边界

V3 的按钮侧栏固定为工作区宽度的 24%。原位编辑触控区左边缘时，右手布局会在按钮和触控区之间留下越来越大的空白。

V4 保留原始触控容器的基准宽度；编辑时增加以下联动：

- **右手模式**：拖动触控区的**左边缘**向右内缩，左侧翻页按钮变宽，延伸到新触控边界之前。
- **左手模式**：拖动触控区的**右边缘**向左内缩，右侧翻页按钮变宽，左右镜像对称。
- 调整另一侧边缘时，翻页按钮宽度不受影响；上下边缘保持独立编辑。
- 两个翻页按钮保持竖向排列，各自高度比例及上下间隔不变；按钮不侵入触控区，仍可点击。

联动计算（浏览器使用真实 DOM 尺寸，单位为 px）：

```text
工作区宽度 = W
原始侧栏宽度 = B
触控容器宽度 = T
固定间隔 = G = 9 px
相邻边距比例 = N (%)

B = W - T - G
侧栏当前宽度 = B + T × N / 100

右手 N = 左边距 left
左手 N = 右边距 right
```

**验收实例**：1440 × 960 px 桌面原型中，右手侧栏初始宽度约 **68 px**；将 `left` 从 0% 改到 25%，触控区相应内缩约 52 px，侧栏变为约 **120 px**，与触控区保持约 9 px 的间隔。

### 3.3 四边独立编辑（继承 V3）

进入单手模式，选择左手或右手，点击手机模式栏的铅笔图标；可直接拖拽触控区上的**上、右、下、左**四个圆形手柄，或者使用工作台右栏的四个滑块精细调节。

1. 当前预览立即更新；右手的左边缘和左手的右边缘同时触发侧栏联动。
2. 四边边距分别表示当前触控**容器**的百分比内缩量。
3. **宽度下限**：保留至少 42% 的触控容器宽度，满足 `left + right ≤ 58%`。
4. **高度下限**：保留至少 40% 的触控容器高度，满足 `top + bottom ≤ 60%`。
5. **取消**：抛弃当前草稿，恢复上一次保存的布局。
6. **恢复默认**：仅将当前草稿四边设为 0%，仍需要点击**保存**才持久化。
7. **保存**：分别记录左手、右手的边距，刷新原型可恢复（前提是浏览器允许本地存储）。

桌面右侧调整条主要服务设计评审；Android 客户端建议保留原位拖拽和无障碍键盘/方向调节等能力。

## 4. Windows 小窗（回归第二版）

### 4.1 视觉组成

桌面背景采用浅蓝色 Windows 风格模拟桌面，中央小窗恢复第二版的版式：

1. 顶部白色标题栏：粉色应用标识、**映点 Pointa**、关闭到托盘按钮。
2. 主内容状态：绿色状态点 + **等待手机连接**。
3. **左侧二维码 / 右侧六位设备码**并排；设备码下方为复制按钮。
4. 底部“激光覆盖层已就绪”卡片，强调鼠标穿透、不需要将配对窗口保持置顶。
5. 窗口底栏：局域网等待配对状态和**刷新配对码**。
6. 桌面底部：模拟任务栏与映点托盘图标。

V5 的 Windows 模拟窗口约 **365 × 410 px**（V4 为 **365 × 455 px**），外层桌面舞台仍约 **575 px** 高；保留窗口的原有内容、宽度与上方元素位置。通过压缩 `.winBody` 的可伸缩剩余空间，使状态卡 `.winDev` 下沿至 `.winFooter` 的间距由约 **71 px** 缩至 **26 px**（含原有 17 px 底部内边距），窗口自然更紧凑。窄屏缩放逻辑不变。

### 4.2 交互

- 点击窗口关闭图标：隐藏配对窗口，显示“已收进系统托盘”的提示；不模拟断开服务。
- 点击任务栏映点图标或“重新打开小窗”：恢复配对窗口。
- 点击刷新配对码：前端生成新的**六位模拟号码**并更新显示。
- 点击复制设备码：浏览器允许时尝试写入剪贴板；否则显示当前码作为备用提示。
- **二维码只用于布局评审**，有“原型示意”角标，未经真实编码，不能用于实际设备配对。

Windows 原生版需另外实现托盘图标、配对服务、二维码和会话安全等实际逻辑。

## 6. 个性化设置

### 6.1 “激光颜色”改为“主题颜色”

设置卡片名称沿用 **主题颜色**。V5 对“黑色 · 默认”采用**无额外彩色主题**的表现：上一页和下一页在全屏、单手、纯翻页、陀螺仪模式下统一使用原有的深蓝黑色按键（背景 `#263246`，边框 `#344052`，移除下一页的强调阴影）；开启状态的小开关、拖尾时间和灵敏度长条进度条使用浏览器/操作系统提供的系统高亮色（CSS `Highlight`），而非人为指定灰色。右侧原生 range 输入使用 `accent-color: auto`。其他五种彩色主题仍按 V4 各自的色值生效，原有滑块形状、长度、数值和交互规则均保持不变。

| 色板名称 | 值 | 说明 |
|---|---|---|
| **黑色 · 默认** | `#3B3F46`（兼容标识） | 色板显示 `#111722`；翻页按钮使用原有 `#263246` 深色；小开关和滑块随系统高亮色 |
| 珊瑚红 | `#FF6475` | 接近第一版的暖红主题 |
| 薄荷绿 | `#32B894` | 清新主题 |
| 天空蓝 | `#4D95ED` | 冷色主题 |
| 暖金色 | `#D69A47` | 暖色主题 |
| 淡紫色 | `#B58AE9` | 柔和主题 |

切换色板后立即影响当前页面和后续页面；继续读写 `pointa-v4-prefs` 以兼容既有 V4 偏好，用户已保存的五种彩色主题保持不变。`#3B3F46` 仅作为 V4 默认主题的存储标识，**不会再作为实际按钮或滑块的显示颜色**。系统高亮色取决于浏览器及设备系统主题（Chromium 环境中常呈蓝色），无需在原型中写死为具体 RGB 值。**激光光点保持红色示意**，与 UI 主题解耦。

### 6.2 拖尾时间（长条滑块）

- 渐隐拖尾开关：默认开启。
- 拖尾时间滑块：**100–1200 ms，步长 50 ms**，默认 **500 ms**。
- 参考第一版样式，展示一条**完整横向轨道**：已选比例填充色、未选部分灰色、圆形拖拽滑块。
- 滑动时右侧文本即时更新数值，并实时更新轨道填充比例。
- 关闭拖尾开关时保留当前时间值，但滑块禁用并淡化；再次开启恢复原值。

### 6.3 控制灵敏度（长条滑块）

- 灵敏度范围：**10–100%，步长 5%**，默认 **60%**。
- 使用与拖尾时间统一的长条轨道样式，右侧实时展示百分比。
- 原型保存数值；原生端后续需要将其接入触控位移映射与陀螺仪灵敏度处理，测试对不同手机屏幕和分辨率的影响。

### 6.4 音量键翻页（保留 V3）

音量键总开关与“上一页”“下一页”两行独立映射；每行选项为 **无 / 音量 + / 音量 −**。若用户将同一物理按键绑定到两个动作，自动解除另一项并提示。关闭开关时保留映射值但不响应模拟音量按键；Android 只能在 App 前台且能收到相应事件时保证支持。

## 7. 其他页面与交互边界

**纯翻页模式**：沿用第三版两个大按钮、下一页更大、无虚构页码的形式。

**陀螺仪模式**：沿用第三版顶部按住激活区、翻页按钮、归零校准及灵敏度入口；当前 HTML 只模拟按住 / 松开状态。

**激光覆盖层技术边界**：实际 Windows 端应使用独立透明、鼠标穿透、不抢前台焦点的覆盖层。触控与翻页指令分离，严禁直接把激光位移映射为系统鼠标位移。Windows 小窗可以隐藏至托盘，激光覆盖层和连接服务由独立组件维护生命周期。

## 8. 数据结构与实现建议

```json
{
  "schemaVersion": 5,
  "themeColor": "#3B3F46",
  "laserColor": "#FF6475",
  "trailEnabled": true,
  "trailDurationMs": 500,
  "sensitivity": 60,
  "volumePagingEnabled": true,
  "previousVolumeKey": "-",
  "nextVolumeKey": "+",
  "oneHandBounds": {
    "left":  { "left": 0, "right": 0, "top": 0, "bottom": 0 },
    "right": { "left": 0, "right": 0, "top": 0, "bottom": 0 }
  }
}
```

> 该 JSON 是**原生产品建议配置结构**。HTML 原型将偏好与左右手边界拆成两个 `localStorage` 键：`pointa-v4-prefs`、`pointa-v4-rects`。若同源浏览器中存在 V3 数据，V4 首次初始化会尽可能读取 V3 边距和非主题偏好；主题初始化为黑色默认。各版本存储分别维护，避免 V4 编辑覆盖 V3 原始内容。

### Android · Jetpack Compose

- 为触摸区域建立四边归一化边距状态，建议使用 `DataStore` 持久化并做边界校验。
- 在 `BoxWithConstraints` 或测量布局得到真实可用宽高之后，计算相邻边界偏移以及翻页侧栏宽度；为左手和右手实现镜像逻辑。
- 使用 `pointerInput` 处理触控区位移、编辑手柄拖动和取消事件；编辑态禁止触控发出激光数据。
- 用 `Slider` 展示连续轨道和进度填充，设置主题切换时更新颜色方案中的主按钮、选中、开关等变量。
- 音量键事件只在具备前台权限、能收到对应键值时处理。

### Windows · C# / WinForms

- 配对窗口采用第二版窄小窗布局；托盘服务可在窗口隐藏后继续运行。
- 独立激光覆盖层处理渲染、拖尾计时和指针位置；接收端以局域网消息协议接收标准化控制事件。
- 二维码与设备码必须绑定真实的短时会话及设备标识；增加超时、刷新、重放保护、掉线清理等逻辑。
- 实现消息校验以及必要的局域网认证；演示时鼠标、前台应用焦点保持不变。

## 9. 原型使用指南

直接在现代浏览器打开 `pointa_ui_prototype_v5.html`，无需安装外部前端框架、无需 CDN：

1. 左侧菜单切换全屏、单手、纯翻页、陀螺仪、个性化设置、设备连接和 Windows 小窗。
2. 在单手模式切换左右手，点击手机内编辑图标，拖动四条边或调整右侧滑块；对比侧栏宽度变化，选择保存 / 取消 / 恢复默认。
3. 在个性化设置切换主题色、拖尾开关、时间和灵敏度，观察长条进度轨道填充；切回演示页面查看主题按钮变化。
4. 在设备页体验继续演示、扫描和设备码输入的模拟入口。
5. 在 Windows 小窗点击关闭到托盘、恢复小窗、复制码和刷新配对码。
6. 在控制模式中按键盘 `+`、`-`（含数字小键盘）模拟前台音量键翻页，需按当前音量键映射设置生效。
